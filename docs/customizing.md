# Customizing

Four extension points, none of which needs a fork.

| Extension point | Use it to |
|---|---|
| [Handwritten files](#handwritten-files) | Add modules next to the generated ones |
| [Middleware](#middleware) | Cache, log, sign or rewrite requests at runtime |
| [Resource snippets](#resource-snippets) | Add methods to a generated resource |
| [Ejected templates](#ejected-templates) | Change what perseid generates |

## Handwritten files

perseid only overwrites or deletes files carrying its `@generated` marker. In Go, the marker is
the `// Code generated by perseid. DO NOT EDIT.` line.

- Put your own modules next to the generated ones.
- In Go, define extra methods on the generated resource types from any file of the package.
- Files scaffolded on the first generation (README, manifest, error types) are yours afterwards.

## Middleware

Every SDK lets you wrap each HTTP attempt.

| Language | Option |
|---|---|
| TypeScript | `middleware`: `(request, next) => Response` |
| Python | `middleware=` of `Acme(...)` and `AsyncAcme(...)`: `(request, next) => response` |
| Go | `Options.Middleware`: `func(next http.RoundTripper) http.RoundTripper` |
| Java | `addInterceptor`: OkHttp interceptors, also added to a client given to `httpClient` |
| Rust | The `Middleware` trait: `Acme::builder().middleware(...)` |
| C# | `Handlers`: `DelegatingHandler`s, also run in front of your own `HttpClient` |

Middleware runs inside the retry loop, after credentials are set. The first one registered is
the outermost.

A local cache for GET endpoints, in TypeScript:

```ts
const cache = new Map<string, string>();
const petstore = new Petstore({
  apiKey: "sk_live_...",
  middleware: [
    async (request, next) => {
      if (request.method !== "GET" || !new URL(request.url).pathname.startsWith("/pets")) {
        return next(request);
      }
      const hit = cache.get(request.url);
      if (hit) return new Response(hit, { headers: { "content-type": "application/json" } });
      const response = await next(request);
      if (response.ok) cache.set(request.url, await response.clone().text());
      return response;
    },
  ],
});
```

The same in Rust:

```rust
#[derive(Default)]
struct Cache(Mutex<HashMap<String, Bytes>>);

impl Middleware for Cache {
    fn handle<'a>(&'a self, request: Request, next: Next<'a>) -> BoxFuture<'a, Result<Response, BoxError>> {
        Box::pin(async move {
            let key = request.uri().to_string();
            if request.method() != Method::GET || !request.uri().path().starts_with("/pets") {
                return next.run(request).await;
            }
            if let Some(body) = self.0.lock().unwrap().get(&key).cloned() {
                return Ok(Response::buffered(StatusCode::OK, HeaderMap::new(), body));
            }
            let response = next.run(request).await?;
            if !response.status().is_success() {
                return Ok(response);
            }
            let (status, headers, body) = response.into_parts().await?;
            self.0.lock().unwrap().insert(key, body.clone());
            Ok(Response::buffered(status, headers, body))
        })
    }
}

let client = Petstore::builder().middleware(Cache::default()).build()?;
```

## Resource snippets

A file at `.perseid/templates/<lang>/extensions/<resource>.<ext>` is inlined in the body of that
resource's class, to add custom methods.

| Language | File |
|---|---|
| Rust, TypeScript | `extensions/<resource>.rs`, `.ts` |
| Python | `extensions/<resource>.py`, and `<resource>_async.py` for the async class |
| Java, C# | `extensions/<resource>.java`, `.cs`, and `<resource>_<operation>.java`, `.cs` inlined after that operation's method |

Resource and operation names are in snake_case.

## Ejected templates

```sh
perseid eject typescript   # copies the templates and runtime to .perseid/
```

- Files you keep in `.perseid/` override the built-ins. Delete the others to keep receiving
  upstream updates.
- `overrides` in `perseid.toml` moves the directory.
- `[context]` values reach templates as `sdk.*`.
- `perseid inspect` prints the model templates receive, as JSON.

### Templates

| Template | Renders |
|---|---|
| `api_resource` | Each resource |
| `api_summary` | The client |
| `component_type` | Each model |
| `api_reference.md.jinja` | `api.md`: every method by resource, in the language's call syntax, with its HTTP request and models |
| `docs.jinja` | Macros naming the API in that language, shared by `api.md` and the README |

- A template picks its output file with `set_summary_filename("api.md")`.
- Generated Markdown is never formatted. `generate --check` compares it like the code.
- The scaffolded `README.md` is rendered once, with `examples`: `call`, `list`, `stream` and
  `create`, the operations its snippets call, each `null` when none fits.

### Filters

- `name | ident("snake", "rust")` turns a spec name into an identifier. Cases are `snake`,
  `camel`, `pascal` and `shouty`. Keywords are escaped for `rust`, `python`, `go`, `java` or
  `typescript`.
- `names | idents(case, language, owner)` fails when two names collide.
- `ident` turns punctuation into words and prefixes a leading digit, as described in
  [names](configuration.md#names).
- Descriptions are Markdown, spec HTML converted. The `doc` filter converts other text.

### Template model

| Field | Where | |
|---|---|---|
| `op.errors` | Operations | The schema of each error response by status: `404`, `4XX`, `default` |
| `error_schemas`, `default_error` | Every template | Error schemas, and the API-wide one ([error schemas](configuration.md#spec-support)) |
| `is_error_schema` | Type templates | Whether the type is an error schema |
| `types` | Resource templates | Every schema by name, to read the fields of a request body |
| `type.discriminator_defaults` | Type templates | The discriminator value of a struct that is a union variant |

Union field types, for values of several types such as Stripe's `string | Customer` or
`object | ""`:

- `is_union()`, `union_variants()`, `try_variants()`, `union_decode()`, `union_mode()`.
- Each variant has a `name`, a `json_type`, `items` (what list items look like), `empty` for
  `""`, and a `type`.
- `union_decode()` is `json-type` when no two variants share a JSON type, else `try`: decoders go
  through `try_variants()` and keep the first variant that matches and decodes.
- `union_mode()` is `json` when the JSON type decides, `rules` when object variants have `when`
  conditions (`{property, value}`, no `value` for presence, checked in `object_variants()`
  order), or `best-match` when they list their `required` and all their `properties`.
- Unions also answer `is_json_object()`, so templates that do not handle them keep untyped JSON.
  `union_refs` lists the schemas they reference.
- A struct variant with a string `id` has `id` set to `required` or `optional`.

## Webhooks

`webhooks = true`, at the top level or in a language table, installs a dependency-free
[Standard Webhooks](https://www.standardwebhooks.com) verifier. It also accepts Svix's `svix-*`
headers.

```ts
new Webhook("whsec_...").verify(rawBody, request.headers); // throws WebhookVerificationError
```

| Language | |
|---|---|
| TypeScript | `new Webhook(secret).verify(body, headers)` |
| Python | `Webhook(secret).verify(body, headers)` |
| Go | `wh, err := NewWebhook(secret)`, then `wh.Verify(body, r.Header)` |
| Rust | `Webhook::new(secret)?.verify(&body, &headers)` |
| Java | `new Webhook(secret).verify(body, headers)` |
| C# | `new Webhook(secret).Verify(body, name => Request.Headers[name])` |

- Payload models come from `webhooks` and `x-webhooks` in the spec, which may be all it holds.
- In Rust, the verifier is always generated, behind the `webhooks` cargo feature, so
  `--all-features` builds (docs.rs) work whatever the setting.
- The TypeScript verifier has no Node.js imports: it runs in browsers, Workers and edge runtimes.
